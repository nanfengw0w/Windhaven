# 场景布局与扩展

## 坐标与共享地形

场景以 XZ 为水平面、Y 为高度。`src/core/config.js` 中的 `TERRARIUM_BOUNDS` 描述 12×8 的原中心区域，`LANDSCAPE_BOUNDS` 描述 24×16 的完整地图。扩展应使用完整地图边界，不要通过修改中心常量重新分布已有景物。

地形高度由 `src/simulation/terrain-shape.js` 和 `landscape-shape.js` 统一计算；可见网格由 `src/terrain/mesh-geometry.js` 和 `landscape-geometry.js` 构建。地表字段、导航、植被和建筑接地都使用同一套高度与布局数据。

`src/layout/` 保存山体、铁路、村镇和道路等共享计算，不创建可见场景对象。调整建筑位置时应同时核对模型足迹、局部整地、入户道路、草木净空和探索碰撞，避免出现画面与导航使用不同位置的情况。

## 山地、铁路与村镇

`world-layout.js` 汇总场景布局，`town-layout.js` 与 `building-model-layout.js` 保存建筑落点和模型尺寸。山地形成湖河背后的景观层次，后山步道连接山体附近的遗迹。

铁路路线和切坡由共享布局决定，轨道、道砟、支墩与隧道由 `src/landmarks/` 创建。列车沿路线更新位置和俯仰，烟尾保持在世界空间。调整铁路时需要同时检查列车净空、桥墩接地、隧道裁剪和出入地图的位置。

`town-grounding.js` 为住宅、钟楼与站房计算落地高度，采用局部挖填和柔和坡肩，使相邻房屋之间保持自然起伏。可见地表的细分精度必须能够表示建筑脚下的高度场，不能只让数学采样贴地而让实际三角网格留下缝隙。

`town-paths.js` 生成主街、入户支路、钟楼与站房通道。门前支路先沿门朝向离开建筑，再转向主街；模型存在偏心门或 L 形翼部时，路径应避开真实墙脚。土路通过 `terrain/town-path-texture.js` 混入地表材质，草地遮罩复用同一条路网，没有额外悬浮覆盖网格。

`landmarks/landmark-surfaces.js` 为程序化结构提供砌石、踏石、木纹、道砟和瓦面细节，并接入共享湿润与霜雪字段。导入房屋和列车的运行资源见 [MODEL-ASSETS.md](MODEL-ASSETS.md)。

## 树木、岩石与草地

小屋周围的 `VegetationSystem`、外围的 `LandscapeVegetationSystem` 和湖岸的 `WillowSystem` 分别管理生成与渲染批次。树木功能统一通过 `tree-registry.js` 暴露的 `ctx.trees` 查询；鸟类栖点、雷击、落叶、果实和交互不应再另存一份树木列表。

`woodland-layout.js` 使用固定种子、林区配置，以及坡度、水域、道路与间距约束生成树石。`woodland-rocks.js` 按旋转后岩石底部顶点采样地形，修正陡坡上的悬空；贴地不改变水平落点。新增地标应在实际足迹附近过滤植被，避免过宽净空形成不自然的大裸地。

草地由整张适生度网格和统一的树荫、裸土及道路遮罩生成，不按旧中心边界截断草簇。`landscape-grass.js` 将全图草分成可裁剪的空间批次，共享材质和实例属性；LOD 根据相机投影高度选择细分，并使用滞回减少频繁切换。

湖岸柳树由拱形主枝和连续下垂的细枝叶带构成。`willow-dynamics.js` 以分段弹簧和局部风场重建枝条中心线，根部固定、末梢较软；颜色与阴影共享位移。风刷在命中的树冠位置补充风力。柳树春季飘少量柳絮、秋季转黄落叶、冬季落叶，普通树木仍沿用各自的季相逻辑。

Hand 工具可拖弯普通树冠，松手后弹性恢复。`TreeInteractionController` 负责拾取、地形遮挡、固定树根和取消交互；切换工具或取消指针时必须清理拖拽状态。

## 花田、麦田与道具

`sunflower-placement.js` 布置湖前到村落西缘的花带，避开湖岸、树石、铁路、房屋与路径。向日葵使用实例化绘制，与阴影共享风摆和追日变形；盛花期追随实际太阳，夜间保留最后的日间方向。四季通过连续季节值控制幼苗、盛花、种盘与枯茎。

`landscape-flowers.js` 管理外围野花，保留与中心野花一致的尺寸、风场和季节变化。修改物种或避让规则时应核对中心与外围两处布置逻辑。

湖前偏左的麦田由 `landmarks/farm.js` 协调。作物使用 GPU 实例批次，随季节从青苗变为麦穗和冬季低茬，风刷和自然阵风共同影响麦浪。稻草人使用独立加载的模型，农具棚、草捆和麦田地表由程序生成。

`props/` 管理中心小屋、庭院、栅栏、码头、小船和系泊绳。小船动力学仍向生态系统提供位置与交互接口。西侧林间木工小院由 `layout/woodworking-layout.js` 定义棚、木堆、木车、树桩和通道，景物与地表纹理分别由 props 和 terrain 模块构建。

后山步道的共享布局位于 `src/layout/`，`props/hiking-trail.js` 构建可见细节。遗迹模型及地形承托由 `props/mountain-ruins.js` 和 `mountain-ruins-model.js` 管理。调整地标时，先改变共享布局，再核对渲染和植被净空。

## 水域、天气与生态范围

湖面、河道和瀑布由 `src/water/` 绘制；导航使用 `simulation/water-surface.js` 的纯数值采样。地图中的可游泳水面、装饰冰色和可承重冰面具有不同含义，不应仅凭颜色决定碰撞状态。

`core/weather-extent.js` 协调完整地图上的天气范围。云、雾、降水与风的水平边界使用完整地图尺寸；云影、降水源和视觉云层必须使用一致的高度。日月轨道由 `sky/celestial-orbit.js` 提供，显示、拾取和拖拽调时共用此计算。

鸟类、落叶和雷击从共享树木注册表获取目标。蝴蝶通过 `life/butterfly-habitat.js` 从实际花卉实例中寻找栖点，并避让水面、建筑、轨道、岩石和陡坡。萤火虫的栖息地受草地、积雪和地标约束；蜻蜓围绕湖面活动。扩展生态效果时应保留独立随机源，避免改变其他系统的生成序列。

## 修改与检查

修改共享空间布局后，重点检查：

- 地形、模型墙脚、道路和可见草地是否使用一致的位置与高度。
- 铁路、车辆、隧道和地图边缘是否有穿插或净空不足。
- 晴天、雨雪、昼夜变化下，材质、阴影与深度遮挡是否一致。
- 第一人称能否正常贴地、进出浅岸，是否仍受建筑和地图边界限制。
- 高低画质、近距离观察及窗口缩放后是否出现接缝、悬空或裁剪异常。

开发服务器可使用 `?inspection=terrain`、`?inspection=models` 和 `?inspection=willows` 检查场景局部；F2 镜头测试可以复制准确机位。`?stats` 提供帧间隔、CPU 提交时间和绘制信息。

代码修改后运行 `npm run baseline:update`、`npm test` 和 `npm run build`。静态检查不执行 WebGL，实际画面与交互需要在浏览器验证。本发行版不依赖旧源码快照或历史截图报告。
